# Windows x64 cffi notice correction

The observed Windows candidate from source `da634ab491076353d769681292ff174c9abfd3c5` lacks file-specific copyright attributions for the cffi 2.0.0 libffi sources selected by the upstream Windows x64 MSVC build recipe. Its descriptor `d32cad7654cc32027037ec3f7b412823b177396c3252f1353eba5d5f48872bd9` remains unapproved. The current Windows bundle retains those source notice blocks; a corrected native producer build and its own input review remain necessary.

The [cffi 2.0.0 source archive](https://files.pythonhosted.org/packages/eb/56/b1ba7935a17738ae8453301356628e8147c79dbb825bcbc73dc7401f9846/cffi-2.0.0.tar.gz) has SHA-256 `44d1b5909021139fe36001ae048dbdde8214afa20200eda0f64c068cac5d5529`. Its `setup.py` selects the `src/c/libffi_x86_x64` C files except `win32.c` and links `win64.obj` for 64-bit MSVC. The selected `ffi.c` notice names Ranjit Mathew, Bo Thorsen and Roger Sayle and requires the copyright and permission notices to be included. The observed bundle's cffi notices and CPython libffi notice did not name those holders. The [retained notice](../../release-notices/windows-x64-cpython-3.13.17/cffi-2.0.0-libffi-notices.txt) contains the complete notice headers for selected C files and relevant headers; `fficonfig.h` and `win64.asm` contain no copyright notice. The [component map](../../release-notices/runtime-components.json) records source file hashes, selected wheel identity and the notice hash. The recipe establishes expected source selection, not independent proof of the wheel's build provenance.

This is a bounded technical correction, not legal advice, release approval, trusted producer authentication or evidence of clean-host behavior. Windows and ARM notice-set approval, flow review and human authorization remain separate.
